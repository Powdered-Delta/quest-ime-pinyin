## 最小完整接入切片

1. 抽出中文会话／后端接口，结果包含原始 composition、带 ID 和消费范围的候选、提交文本及编辑动作，保留固定后端作回归。
2. 固定数据库来源、摘要和独立数据许可；在模块可访问的私有位置校验安装。模块 assets 与宿主 context 不同，必须先验证实际读取路径，不能假定宿主 assets 含模块资源。
3. 复用只读 SQLite 连接，在单一 worker 查询、前缀整理及排序；主线程只做 UI 和输入连接编辑。
4. 结果携带目标身份、会话代次和组合版本；切字段、语言或快速连续输入后丢弃过期结果。按键动作保序，不能让空格抢在尚未完成的查询前。
5. 规范化拼音时保留到原始字符串的坐标映射；支持不完整前缀、显式分隔符、完整词组优先及部分消费。不要只复制 SQL 而遗漏候选整理和消费语义。
6. 保持现有 HostAdapter/UI 和编辑事务契约；候选来源从 fixture 切到真实后端。初始化／查询失败保留已输入文本并显示可恢复状态。
7. 本地资源检查、纯候选测试、Windows 构建后，获得设备操作授权再验证模块资源可访问性、线程、浏览器和焦点生命周期。

## 验收输入

- nihao / woshi / shurufa：完整候选，不要求逐字选。
- h / ha / nih / niha：不完整前缀仍有稳定候选。
- nihao 选 ni 单字、nih 选 ni 单字：后缀继续组合，不连带字面上屏。
- ni'hao / xi'an：分隔符映射、消费范围及剩余组合正确。
- 快速打字、退格后旧结果、切字段、切语言、空格及 Enter 保序。
- 初始化失败、空候选及失效连接保留文本；主线程无数据库查询。

## 繁体扩展方向

保留 Pinyin 作为项目核心，不将简体写死在候选 UI。后端方案可声明自己的输出字形、词库及排序；简体、繁体可通过独立方案选择，宿主只消费统一候选契约。

繁体贡献应说明词库／转换来源、地区词汇、词频和多对多字形转换行为。单字机械替换不能自动保证繁体词语与上下文正确。先完成一个真实简体后端，再接繁体方案，避免把尚未实现的配置写成已支持功能。

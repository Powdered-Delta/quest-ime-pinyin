# 输入行为规范

本规范整理当前系统键盘原型约束及下一阶段必须保持的契约。固定词表只用于验证接入；不完整拼音的候选行为同样适用真实词库。

## 组合与候选

- 原输入框是文本事实来源；会话保存未提交拼音和候选，不另存一份完整用户文本。
- 不完整前缀仍须有稳定候选：h/ha 可匹配 hao；nih/niha 可保留 ni 单字和可补全词组。
- 每个候选具有会话内稳定标识、文本和原始 composition 的消费范围。当前后端以 PinyinCandidate.id 和 consumedEnd 保存标识及原始消费末端；UI 快照以 generation 和输入连接身份保护点击。
- 选词只提交候选文本、删除其消费范围和相邻多余分隔符；余下拼音继续组合并重新生成候选。
- 预测补全消费用户实际输入的字母，不能按补全后的拼音长度删除。ni'h 中选择尼，应保留 h；h 中选择好，消费 1 个已输入字母。
- 候选去重与稳定排序在引擎层；UI 不根据字数猜消费长度，不把未知后缀一并上屏。

| 操作 | 当前模块行为 |
|---|---|
| 字母 | 追加到未提交组合，更新候选及下划线 |
| 选“你好” | 提交该候选，消费对应拼音 |
| nihao 选“尼” | 提交尼，保留 hao 并显示好等候选 |
| nih 选“尼” | 提交尼，保留 h 并显示 hao 前缀候选 |
| 空格（有候选） | 选首候选，不额外加空格 |
| Enter（有候选） | 当前原型选首候选；与另一个应用内 IME 的原拼音 Enter 约定有区别，不直接照搬 |
| 无候选空格／Enter | 按当前会话规则提交原文；空组合 Enter 执行编辑器动作 |
| 退格 | 优先删除组合；空组合交给原编辑器，不能先发空 COMPOSE 导致双重删除 |
| 焦点／输入连接变化 | 旧组合和候选失效，不向新目标提交旧结果 |

## 编辑事务与字段

部分提交 TEXT + 剩余 COMPOSE 必须成批，不让中间无组合状态的选区通知终止新组合。候选点击、外部光标移动和原系统回调不能各自重复完成同一次提交。

普通文本及已验证的 URI 布局可使用中文。密码、可见密码、网页密码、邮箱及非文本类型沿用原系统行为，不查询或缓存敏感输入，不记录文本或候选内容。模块日志仅限宿主状态、类型、尺寸和数量。

## 候选 UI

- 顶部只显示候选，没有模式标签或重复拼音；本次组合的下划线在镜像及支持样式的原编辑器中显示。
- 按候选真实测量宽度、间距和条件展开按钮算出 X；不能固定前 5 项，也不能靠水平滚动掩盖溢出。
- 展开区只显示 X 之后的候选，与键盘同宽同高，向下覆盖按键区；候选增减不移动或缩放原空间面板。
- 两区域共用文字、背景、按压效果；左容器边距和左 padding 为 0，保留候选文字内部点击留白。
- 选择候选、修改组合、切换输入法或结束输入会收起展开层；无余项时不显示展开按钮。
- 本次组合范围只标记当前光标前的匹配串，不对原文中其他同串加线。

## 验证要求

功能检查覆盖前缀、词组优先、部分消费、分隔符、旧点击、焦点切换和编辑批次。本地构建不能证明 VR 射线／手势交互；截图只能证明该时刻布局，不能证明点选或滚动。

截图必须每次先请求准备确认并等待“准备好了”，用户跳过则不拍。0.10 的截图复验已明确跳过。

## 异步候选与资源

数据库初始化、摘要、完整性校验、查询及关闭均在单一 worker。按键动作和选词按顺序处理，结果按顺序回到 owner 线程；不能为丢弃旧候选而一并丢弃已接受的提交动作。待处理期间隐藏旧候选，避免选择即将失效的列表；字段／会话变化以 epoch 取消旧工作及其回调。

语言切换等待已接受动作完成后再确认原拼音并切换。查询失败保留当前组合并提供重试；重试同样核对原编辑目标和会话，不能在保护字段上恢复查询。真实词库来源和固定摘要见 assets/ime/notices/PROVENANCE.md。

# 版本控制与发布规范

## 分支与提交

- main 是可构建集成主线，不代表每个提交都已通过设备验收。
- 功能分支使用 codex/<功能>；修复和文档同样按独立行为范围拆分，不混入原应用改动。
- 一次提交完成一条可检查的行为链；提交前运行适用验证和 git diff --check。
- 禁止伪造 0.3～0.10 的 Git 历史；它们仅是独立建仓前的设备测试编号。
- 不重写已共享历史，不自动推送，不提交签名、缓存、日志、APK 或原系统文件。

## 版本与构建标识

- 0.10-probe / versionCode 10 保留为历史原型基线。
- 0.0.1 / versionCode 20 为首个独立项目版本；包名为 `com.m0e_n00b.questimepinyin`。
- 后续使用 major.minor.patch 与 alpha.N / beta.N / rc.N 预发布标识。
- 新词库能力基线为 0.11.0-alpha.1；后续 patch 表示修复，minor 表示新增能力。0.x 阶段不承诺后端接口稳定。
- Android versionCode 为正整数，每次向设备分发新版 APK 时严格递增；不能从语义版本字符串直接推导，也不能回退为 1。
- 日常源码、测试和文档提交用 Git 提交号区分，不为每次修改涨版本。
- AndroidManifest.xml 是安装版本唯一来源；构建清单同时记录提交号、工作区是否干净、版本、APK 摘要、词库摘要和宿主指纹。

## 基线、标签与产物

- 使用 baseline/probe-0.10 固定已导入源码。baseline 标签不宣称正式发布或重新设备验收。
- 只有完成该版本必需验证后才创建 v<versionName> 发布标签。预发布也须记录未验证范围，不能以构建成功冒充设备通过。
- 标签不移动；错误通过新提交／新版本修正。签名后的 APK 摘要属于该次产物，不用它代替源码提交号。
- 发布记录包含对应提交、构建工具、签名证书指纹、词库来源／摘要、宿主版本／摘要、本地检查和设备验证边界。
- 本地忽略的 build/ 可保存产物及构建清单；需要公开分发时由维护者单独选择平台，源码仓库不直接存 APK。

## 当前阶段

真实词库已进入 0.11.0-alpha.1 基线；alpha.2 修复全角标点及长按滑选替换语义，alpha.3 修复 Enter 提交原始拼音，alpha.4 修复首次布局尺寸监听，alpha.5 改进展开候选宽度排列，alpha.6 保留组合内光标移动，alpha.7 支持组合内退格与插入，alpha.8 修复光标内移动时的组合下划线和 composing 范围恢复，alpha.9 修复移动光标后候选／空格提交的 composing 替换，均待设备交互验收后再决定是否创建发布标签。
